# Project S V2.1: engineering report (sources, reliability, safety)

Date: 27 November 2026 · Created by Shivanshu Sharma

The UI was kept as it was. Everything below was added on top of V2 and the PDF maker.

## 1. What changed

### Real, verified sources (owner's request: "har baat ka source, koi fake source nahi")
- New setting **🔗 Har fact ke saath real source** (on by default). It turns on web search and tells the AI to cite every fact only with `[n]` from S's own search results, never to invent a source, URL or book, and to mark claims without a source as "⚠ no source found: general knowledge, please verify". Calculations are labelled "Source: calculation".
- **Source check box** under every answer, worked out by S itself (not by the AI):
  - counts the real sources (links that came back from S's web search / page reader, or Claude's own search),
  - flags `[n]` numbers that don't match any source,
  - flags links the AI typed that did not come from search,
  - warns when a factual answer has no source at all,
  - notes when a SymPy calculation actually ran.
- **🔍 Links check karo** opens each source page and checks whether the words of the sentences that cite it appear on the page. Result per source: ✓ opened + n/m words matched, ⚠ opened but low match, ✗ could not open. The app says clearly that a word match means "same topic", not a 100% guarantee.
- Claude's web-search citations are now turned into the same `[n]` numbers and source list.
- Limit: S can't force an AI to cite every sentence. The check box shows when it didn't.

### Reliability
- 45 s limit for a server to start answering; if an answer stream stops for 60 s, S stops waiting and says so.
- One automatic retry (after 2 s, or the server's `Retry-After` up to 10 s) for timeouts, dropped streams and 5xx errors, only if nothing was shown yet. Claude SDK: 2 retries, 2-minute limit.
- If an answer breaks half-way, the part that arrived is kept (marked "Jawab poora nahi aaya") and Retry asks again.
- No double sending (double tap / Enter + tap), at least 1.2 s between messages, at most 20 messages a minute.
- Stop button still works with the new time limits.

### Conversations
- **Folders:** 📁 on each chat, folder filter in the sidebar; new chats go into the folder that is open.
- **Search** now also looks inside messages (3+ letters), not just titles.
- **Export a chat** from the 📄 top-bar button: PDF, Markdown or JSON.
- **Auto titles:** after the first answer, one small extra request writes a 2–6 word title (setting, on by default; renaming by hand stops it).
- **Long chats:** when old messages no longer fit, their questions (and the start of each answer) are passed to the AI as a summary, instead of being dropped silently.

### Memory
- Memory **never saves private details**, even if the AI tries: phone numbers, emails, passwords/PIN/OTP, API keys, Aadhaar/PAN/passport/ID numbers, bank/card/UPI details, addresses. The user sees "🔒 Private baat thi, isliye save nahi ki".
- Every memory save shows a toast with **Undo**.
- **🕶 Temporary chat** (sidebar): not saved to history, memory not shown to the AI, memory tool off.
- View / edit / delete / add / turn off memory (from V2) were re-checked.

### Backup
- Backup includes safe settings (mode, language, style…) from a fixed list. **No keys, no server URL.** If a key was ever pasted inside a chat, it's replaced with "[API key removed]".
- Restore checks the file first (valid JSON, chat format, roles), shows counts, and asks before changing anything. It **merges**: existing chats are never deleted, and when a chat exists in both, the newer one wins. Private facts in the backup's memory are skipped. Settings are only applied if the user agrees, and keys in a backup are ignored.
- "Delete all chats" now offers a backup first.

### Files
- Checks the real file content, not just the name: empty files, fake PDFs (no `%PDF`), fake Word files (not a zip), binary data in "text" files, broken photos.
- PDFs: page count and size in the tray, 🔒 warning for password-locked PDFs.
- Clearer messages when a Word file can't be read. The AI is told to answer only from the document, quote the line, give section/page-wise summaries, and say so when the document doesn't contain the answer.

### Voice
- **🎤 Mic test** in Settings → Voice: shows what it heard, or a clear reason (permission blocked, no mic, no speech, needs internet, browser not supported).

### Security
- New setting **🔑 Keys is device pe yaad rakho**. Off = keys are kept only for the open tab (sessionStorage) and vanish when it closes.
- **Own server (optional):** `backend/worker.js` is a Cloudflare Worker that keeps the Gemini key as a server secret, with an origin allowlist, model allowlist, size limit and per-IP rate limit. In S: Settings → AI → "Apna server" (`https://….workers.dev` only; added to the CSP). Guide: [BACKEND.md](BACKEND.md).
- Privacy text updated. S does not claim browser-stored keys are secure.

## 3. What failed / was not tested

- No failing tests at the end of this phase.
- **Real AI answers** (good key): not tested, no real key in the build environment.
- **Real Wikipedia, r.jina.ai page reader and OpenRouter**: blocked by the build environment's network, so web search and "Links check" were only tested with mock pages.
- **Real microphone and voices**: tested with fake browser speech objects.
- **iPhone / Safari (WebKit)**: no WebKit browser in the build environment.
- **The Worker on real Cloudflare**: only tested in Node with a fake Google server.

## 4. What needs a backend

- One shared key that users never see → the optional Worker (built, not deployed).
- Login, cloud sync of chats between devices, strict global rate limits, abuse protection → not built (needs an account such as Firebase / Supabase / Cloudflare KV owned by the project).

## 5. What needs external API keys

- Every AI answer: Gemini (free daily limit), OpenRouter (free models), Claude (paid).
- Auto titles use one extra small request on the same key.
- Google Search inside Gemini usually needs a key with billing; otherwise S uses Wikipedia (no key).
- Wikipedia and the page reader (r.jina.ai) need no key.
